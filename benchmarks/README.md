# Comparable wire benchmark

Run it with:

```text
cargo bench --bench compare
```

The harness uses one collection-heavy message shape: three roles, eight attachments, and three metadata entries. It reports encoded size, encode time, owned decode time, borrowed decode plus full iteration time, and allocation count for Typikon, FlatBuffers, and a TL-style layout.

The TL-style fixture is a local reference implementation, not Telegram's generated schema or a third-party TL runtime. It uses synthetic constructor IDs, little-endian fixed-width scalars, aligned TL strings, the canonical `vector` constructor, and a vector of key/value entries for metadata. TL has no universal native map representation, so the metadata representation is explicitly a canonical vector of pairs.

FlatBuffers uses the checked-in schema in `collection.fbs` and code generated by `flatc`. Its borrowed path reads the generated table and vectors directly from the input buffer; its owned path copies strings and materializes collections.

The benchmark is a local CPU/memory baseline, not a network benchmark. Run all formats on the same machine and build profile before drawing conclusions.
